# Database Notes

This document covers database management, common commands, and troubleshooting for the **Come2Kids** project.

---

## Overview

The project uses PostgreSQL as the primary relational database.

---

## Permissions Model (Two-Layer)

Since T-1.5.4 (RBAC refactor) the platform uses two independent permission layers:

1. **Platform layer** — `users.platform_role` (`user` / `moderator`).
   Global capabilities (moderation queue, blocking, appeals) are checked
   against this column. An unauthenticated requester is a Guest.

2. **Organization layer** — `company_members` + `roles`.
   A membership row `(organization_id, user_id, role_id)` with a composite
   primary key defines what a user can do inside a specific organization.
   The `roles` reference table is seeded with `owner` (id 1) and
   `manager` (id 2); these ids are a fixed contract used by the partial
   unique indexes:
   - `idx_company_members_one_owner_per_org` — one owner per organization;
   - `idx_company_members_one_org_per_user` — one owned organization per user.

`organizations.owner_id` no longer exists: ownership is expressed by a
`company_members` row with the owner role. Assigning `owner_user` before
saving a new `Organization` automatically creates the owner membership
(`after_create` callback).

The `email_tokens` table is not part of the baseline: it will be introduced
with the registration user story (US-2.1). There is no `refresh_tokens` table:
login returns only a short-lived JWT access token (`DropRefreshTokens` migration).

## Common Rails Database Commands

Execute these commands from the `api/` directory.

* **Create the databases defined in `config/database.yml`:**
```bash
rails db:create
```

* **Run pending migrations:**
```bash
rails db:migrate
```


* **Populate the database with seed data:**
```bash
rails db:seed
```


* **Completely reset the database (drops, creates, migrates, and seeds):**
```bash
rails db:reset
```


* **Check the current migration status:**
```bash
rails db:migrate:status
```


* **Rollback the last migration:**
```bash
rails db:rollback
```

## Schema Management

The database schema is defined in `api/db/schema.rb`. This file is auto-generated by Rails and should never be edited manually. Always use migrations to alter the database structure.

### Creating a New Migration

To create a new migration, use the Rails generator:

```bash
rails generate migration AddFieldNameToTable field_name:type
```

**Example:**

```bash
rails generate migration AddEmailToUsers email:string
```

## Troubleshooting

### Connection Refused

Ensure the PostgreSQL service is actively running:

* **Windows:** Check Windows Services for `postgresql-x64-18`.
* **macOS:** Run `brew services start postgresql`.
* **Linux:** Run `sudo systemctl start postgresql`.

### Database Already Exists

If you encounter this error during setup, drop the existing database and recreate it:

```bash
rails db:drop
rails db:create
```

### Cannot Connect to Database

Verify your credentials in `api/config/database.yml`:

```yaml
development:
  adapter: postgresql
  database: come2kids_dev
  username: postgres
  password: YOUR_PASSWORD_HERE
  host: localhost
  port: 5432
```

## Database Documentation

### Seed Data

`rails db:seed` is idempotent (safe to run multiple times) and provides:

- reference data: roles (`owner`, `manager`) and categories (uk/en);
- fixed demo accounts: `moderator@come2kids.dev` (password from the
  `MODERATOR_PASSWORD` env variable), `owner@demo.com` / `Owner12345`,
  `user@demo.com` / `User12345`;
- a demo organization `demo-events` with two events (uk/en translations);
- Faker-generated sample organizations and events (uk locale);
- **user avatars**: JPEG images attached to moderator, demo owner, and regular user (stored via Active Storage, max 5MB, validated content type).

### Active Storage (T-2.5.2)

User avatars are managed via Active Storage with the following features:

- **Storage backend**: local disk (`storage/` directory in development)
- **Validations**:
   - content type: `image/jpeg`, `image/png`, `image/webp`
   - size: maximum 5MB
- **Access**: use `user.avatar.attached?` to check, `user.avatar_url` to get the relative path
- **N+1 prevention**: use `User.active.with_attached_avatar` scope when loading users with avatars

Active Storage adds three tables:
- `active_storage_blobs` — file metadata (filename, content type, checksum)
- `active_storage_attachments` — polymorphic join table (links User/Organization to blobs)
- `active_storage_variant_records` — image variants (thumbnails, resized versions)

The legacy `users.avatar_url` column was removed; all file uploads now use Active Storage.
